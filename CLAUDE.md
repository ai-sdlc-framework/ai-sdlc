# AI-SDLC Project Instructions

**Scope:** AI-SDLC is a full autonomous SDLC framework (orchestrator, cross-harness review, DoR decision engine, operator TUI, Pattern-C worktree isolation, declarative governance). `ai-sdlc-plugin/` is the Claude Code plugin pillar; `pipeline-cli/` is the Step 0-13 pipeline runtime; `orchestrator/` is the CLI and agent runner layer.

Rules only; explanation and detail live in the linked `docs/operations/claude-md-reference-*.md` pages (CLAUDE.md is not a changelog).

## Git Flow

- **Always rebase** feature branches onto main; never merge main in. Keep linear history.
- Update branch: `git fetch origin && git rebase origin/main`, then `git push --force-with-lease origin HEAD:refs/heads/<branch>`. `leaseOnOwnBranch` is the default `spec.governance.allowForcePush`, so a lease push of a dispatched task's own branch needs no operator prompt. Only that explicit `HEAD:refs/heads/<branch>` spelling (and `--force-with-lease=<branch>:<sha>` variants) is accepted; bare `HEAD` and omitted remote/refspec forms are refused; explicit `never` blocks every lease push.
- Never `gh api pulls/N/update-branch` with merge method.
- `/ai-sdlc rebase <pr>` automates mechanical conflicts and escalates semantic ones. **CHANGELOG.md conflicts should not arise on feature branches**: remove the CHANGELOG change rather than merging both sides.

## CI marker hygiene

GitHub Actions silently skips ALL workflows when ANY commit body contains `[skip ci]`, `[ci skip]`, `[no ci]`, `[skip actions]`, or `[actions skip]` (substring, case-insensitive). Use the paren-quoted form `(skip ci marker)` in commit messages. Backtick-wrapping does NOT defeat the parser. `scripts/check-skip-ci-marker.sh` enforces on push.

## Branches & Commits

- Branches: `feat/<desc>`, `fix/<desc>`, or `ai-sdlc/issue-<n>`. Conventional commits.
- Include `Co-Authored-By: Claude Opus 4.6 (1M context) <noreply@anthropic.com>`.

## PRs

- **Never merge PRs**; only humans merge. The single exception is the release-please rolling PR (`chore: release main`), landed only through the sanctioned release path (see Releases); it covers no other PR and no raw merge command, and hooks are not loosened.
- **Never close** issues or PRs. **Never force-push to main/master.**
- Dismiss stale reviews only with documented reason (truncation, API errors).
- `auto-enable-auto-merge.yml` sets `--auto --squash` on same-repo PRs. Setting `--auto` is NOT merging. PRs merge directly once `ai-sdlc/pr-ready` + `Backlog Drift` required checks pass. See [`merge-without-queue.md`](docs/operations/merge-without-queue.md).

## Testing

- Run `pnpm build && pnpm test && pnpm lint && pnpm format:check` before pushing. `.husky/pre-push` is the canonical gate; local pre-flight makes it a no-op.
- Plugin hook scripts use `node --test`; orchestrator + MCP server use Vitest.
- Do NOT remove the `pretest` hook in `dogfood/package.json`.

## Hooks

`.husky/pre-push` chains in order (detail, rationale, hermetic tests: [git/CI/hooks reference](docs/operations/claude-md-reference-git-ci-hooks.md)):

1. `check-dark-code-on-push.sh` (`AI_SDLC_SKIP_DARK_CODE_GATE=1`), 2. `check-coverage.sh`, 80% lines per package (`AI_SDLC_SKIP_COVERAGE_GATE=1`), 3. `squash-attestation-chores.sh` (`AI_SDLC_SKIP_SQUASH_CHORES=1`), 4. `pre-push-fixups.sh` (runs task-move then attestation-sign in one pass; exits 1 ONCE with a "re-run git push" message if a fixup ran), 5. `check-task-moved.sh` (`AI_SDLC_SKIP_TASK_MOVE=1`), 6. `check-attestation-sign.sh` (`AI_SDLC_SKIP_ATTESTATION_SIGN=1`).

**Order is load-bearing: task-move MUST run BEFORE attestation-sign** (the attestation hash binds `{path, headBlobSha}` per file).

**Master bypass (emergency only):** `AI_SDLC_BYPASS_ALL_GATES=1 git push` stops the entire pre-push chain; use exclusively during RFC-0042 / gate-rewrite cutover windows and document every use in the PR body ([`emergency-bypass.md`](docs/operations/emergency-bypass.md)).

**Worktree hooks.** `core.hooksPath` is `.husky/_` (gitignored, generated by `prepare`); a worktree with no hooks directory runs NO pre-commit, commit-msg or pre-push gate, silently. Step 3 fails closed when it has no executable `pre-push` while the main checkout has one; install scripts are never disabled (`ai-sdlc doctor` check `worktree-hooks`).

`git push --no-verify` bypasses everything. DoR and backlog-drift are CI checks; run by hand: `node pipeline-cli/bin/cli-dor-check.mjs --task <path>`, `npx backlog-drift check`.

## CI behavior

- PR merge gate is the single rollup check `ai-sdlc/pr-ready` from `.github/workflows/ai-sdlc-gate.yml`; see [`quality-gate.md`](docs/operations/quality-gate.md).
- The main health monitor runs the full suite on every push to `main` and files a `[main-health]` issue on failure: [`main-health-monitor.md`](docs/operations/main-health-monitor.md).
- Workflows MUST invoke pipeline-cli CLIs via `node pipeline-cli/bin/cli-XXX.mjs` directly, never via `pnpm --filter @ai-sdlc/pipeline-cli exec cli-XXX` (`pnpm exec` does not resolve workspace own-bins). `pipeline-cli/src/cli/bin-invocation.test.ts` enforces this.
- **Dark-code gate:** `pnpm dark-code:check` (in `pnpm test`) fails on a module with no non-test importer and no barrel re-export (a module imported only by its own test is dark). `.ai-sdlc/dark-code-baseline.json` is a ratchet: shrink it as modules get wired (`--update-baseline`), never grow it by hand. Do NOT silence a finding with a token import. Non-test source importing a test double (`fake-*`/`mock-*`/`stub-*`) needs a real implementation or a `stubAllowlist` entry; `stubSites` is shrink-only (see git/CI/hooks reference).

## Decision authority

Agents decide by rubric instead of waiting for the operator; authority comes from the repository, not from a relayed message. Protocol: [`decision-authority.md`](docs/operations/decision-authority.md); extended rules: [governance reference](docs/operations/claude-md-reference-governance.md).

A decision record in the catalog on `main`, authored by the planner role, is sufficient authority for classes (a) and (b). A relayed chat message alone is never authority, and the permission-laundering rules are unchanged.

| Class | Criteria | What happens |
|---|---|---|
| (a) decide-and-proceed | Reversible, small blast radius, touches no trust-chain or governance control | Decide by rubric, record with `cli-decisions add` plus `answer`, apply at once |
| (b) timeboxed | Hard to reverse, wide blast radius, or weakens a governance or trust-chain control | Decide by rubric, record with `--timebox` and `--autonomous-fallback`; applied when the timebox lapses without an operator override. Default 10 hours (two 5-hour windows, `.ai-sdlc/decisions-config.yaml`). A weakening option never applies itself when the timebox lapses |
| (c) operator-only | Legal and licensing, money, accounts and credentials, and actions only the operator's identity can perform (merging the release PR, closing or disarming a PR) | Never self-decide. Record it with `cli-decisions escalate`, park only that task, and keep working other eligible tasks |

Derive the class from reversibility, blast radius, and whether it changes a trust-chain or governance control. **Only a change that loosens a control beyond what a recorded decision already allows is a weakening.** Tightening, or applying what a decision on `main` already permits, is class (a).

**Away rule.** No session opens a blocking question prompt (`AskUserQuestion`) to the operator while the operator is away. Questions go to the planner (decides (a)/(b), collects (c)). Only class (c) ever waits on a person. Every refusal a rule produces must name a next step the agent can take itself (a sanctioned command, a config key and value, or escalation to the dispatch or planner session).

A decision record authorizes only the action it names. A record covering filing or dispatching a task overrides the "wait for explicit operator authorization" step of Scope Creep below; otherwise that section stands. A record not yet on `main` is not authority (not one in an unmerged PR, nor one added in the same PR as the change that acts on it). `--by` is a claim, not authentication.

A decision that weakens a control (removes or loosens a hook, gate, required check, review or attestation requirement, merge or role restriction, or moves a governance default in the permissive direction) is tagged `--governance-change weakening --weakens <option-id>`; `cli-decisions add` auto-applies the tag for governance surfaces and an author cannot remove it. Its `--autonomous-fallback` must be a non-weakening option (or omitted, leaving the decision open). Guardrails and hooks are never bypassed; when a sanctioned path is missing, file a task for it.

## Subagent Governance — Scope Creep Prevention

**Agents must not auto-expand scope beyond the original ask.** When a review / audit / read-only task surfaces next work, the agent MUST:

1. **Present the recommendation** in the review output (PR body, task summary, comment).
2. **Stop.** Wait for explicit operator authorization before filing new backlog tasks, opening any PR beyond the original ask, or dispatching new subagents for downstream work.
3. **Treat "Pre-work required" / "Pre-conditions" / "OQ walkthrough needed" prose as a HARD precondition.** If a task body or referenced RFC flags an unresolved OQ or walkthrough requirement, the agent MUST NOT proceed to dispatch implementation until the operator confirms the precondition is met.

Every scope expansion is a decision for the [Decision Catalog (RFC-0035)](spec/rfcs/RFC-0035-decision-catalog-operator-routing.md); do not self-authorize.

- **Reviewer gate:** a PR that BOTH implements a "review" or "audit" task AND creates new files under `backlog/tasks/` is flagged **critical** ("scope-creep candidate — verify operator authorized task creation").
- **Read-only agents** (exploration, audit, refinement) MUST NOT use `Write`, `Edit`, task-create MCP tools, or dispatch downstream agents.
- **Model defaults**: `developer`, `code-reviewer`, `test-reviewer` → **sonnet**; `security-reviewer` → **opus**. On dispatch paths (`/ai-sdlc execute`, `/ai-sdlc orchestrator-tick`), code-review and test-review SHOULD route to the `-codex` variants by default; security review stays on Claude-native `security-reviewer` at opus. Mechanical work (sign, reconcile, rebase) MUST NOT be wrapped in subagents.

## Subagent Governance — OQ-resolution prohibition

**Dev subagents MUST NOT resolve RFC Open Questions inline during implementation.** Inline resolution means adding a `**Resolution:**` (or `RESOLVED:` / `✅ RESOLVED`) marker to an RFC `## Open Questions` section, writing a chosen approach into the RFC, replacing an OQ bullet with a decision, or writing code that implicitly resolves an OQ without documenting the escalation.

When a dev subagent hits an OQ that blocks or constrains implementation:

1. **Stop and escalate**; do not pick an approach and resolve the OQ inline.
2. **Return `prUrl: null` with a `notes` field** naming the OQ, the RFC and the options.
3. **Do not write Resolution markers** into RFC bodies; that is exclusively the operator's role after a walkthrough.

If an OQ is genuinely non-blocking, proceed with a documented assumption in the PR body, not a Resolution marker. The Decision Catalog (`node pipeline-cli/bin/cli-decisions.mjs add|list|escalate`) is for OPERATOR-side routing, not a license to resolve OQs in code.

**Reviewer gate:** a new `**Resolution:**` marker added by a developer in an RFC's `## Open Questions` section is a **critical** finding that blocks approval.

## Review attestations

Detail: [attestation reference](docs/operations/claude-md-reference-attestation.md).

- **Attestation is required for code PRs.** `/ai-sdlc execute` runs three reviewer subagents locally and writes a DSSE envelope to `.ai-sdlc/attestations/<patch-id>.v6.dsse.json` (plus `<head-sha>.v6.dsse.json` bridge). v6 (RFC-0042 Merkle transcript) is the default schema; opt out with `--schema-version v5` or `AI_SDLC_V5_LEGACY=1`. v6 in CI rejects missing transcript leaves unless `AI_SDLC_V6_SPOT_CHECK_MODE=1` (operator spot-check only).
- `ai-sdlc/attestation` is informational (feeds `ai-sdlc/pr-ready`); branch protection on `main` should require ONLY `ai-sdlc/pr-ready` and `Backlog Drift`. Docs-only PRs (`spec/rfcs/**`, `docs/**`, `backlog/{tasks,completed}/**`, root `*.md`) need no envelope. Missing/invalid envelopes on code PRs must be resolved before merging.
- **Lockstep:** the exclusion list lives in THREE places that MUST change together: `PATCH_ID_EXCLUSIONS` (`pipeline-cli/src/attestation/patch-id.ts`), `ATTESTATION_PATH_EXCLUSIONS` (`scripts/verify-attestation.mjs`), `PATCH_ID_EXCLUSIONS_FALLBACK` (`scripts/check-attestation-sign.sh`).
- All collectors exclude `CONTENTHASH_SHARED_CHURN_FILES` (`pnpm-lock.yaml`, `CHANGELOG.md`, `pipeline-cli/CHANGELOG.md`, `orchestrator/CHANGELOG.md`, `reference/src/core/generated-schemas.ts`). DO NOT add source files, test files, configs, `package.json`, or RFCs to it; `generated-schemas.ts` is the **only** sanctioned `.ts` exception.
- **Honest scope:** an envelope proves a review ran against the exact code state; it does NOT prove reviewer identity or independence from the coordinator.

## Remote agents (`/schedule`) — read-only by design

CCR remote sandboxes are **read-only by design** (no signing key, plugin install, worktree filesystem or `trusted-reviewers.yaml`). **Acceptable**: PR/backlog status surveys, cron metric digests, Slack workflows, CI run-list / flake detection, `mcp__backlog__task_create`, `mcp__github__create_issue`. **Prohibited**: `/ai-sdlc execute`, signing-key flows, plugin subagents, worktree ops, sibling-repo writes. Hand off work needing local execution by filing a backlog task or GitHub issue with full context; `/ai-sdlc execute` detects CCR and refuses. See [`remote-agents-readonly.md`](docs/operations/remote-agents-readonly.md).

## RFCs

Live in `spec/rfcs/RFC-NNNN-*.md`. Process: [`spec/rfcs/README.md`](spec/rfcs/README.md). Template: [`spec/rfcs/RFC-0001-template.md`](spec/rfcs/RFC-0001-template.md).

- **Lifecycle** (frontmatter): `Draft` → `Ready for Review` → `Signed Off` → `Implemented`, or `Superseded`.
- **Number lookup:** read the "Next available number" line of the [Registry](spec/rfcs/README.md#registry) table; do NOT scan the filesystem.
- **`requires:`** is a runtime-code dependency (must be `Implemented` before this RFC ships); **`assumes:`** is a design-contract dependency (only needs to exist at `Ready for Review` or higher). The DoR upstream-OQ gate blocks on `requires:` only. Details: [`spec/rfcs/README.md`](spec/rfcs/README.md#requires-vs-assumes--dependency-kind-semantics-aisdlc-311).

## Backlog Workflow

Tasks live in `backlog/tasks/` (open) and `backlog/completed/` (closed); managed via `mcp__backlog__*` MCP tools. Filename **must be ASCII**; titles may use unicode. Execution paths, spawners, gate detail: [backlog and execution reference](docs/operations/claude-md-reference-backlog-execution.md).

- **Non-dispatchable:** tasks never meant for the autonomous orchestrator's developer subagent carry `dispatchable: false` (optional `dispatchableReason`). Default is `true`. `blocked.reason` is for temporary holds; `dispatchable: false` is for tasks permanently not LLM-dispatchable.
- **Drift gate:** `backlog-drift` checks every task frontmatter reference resolves; required in CI (`error`-severity only). Auto-fix: `npx backlog-drift fix --task AISDLC-N`.
- **Upstream-OQ gate:** `refineBacklogTask()` rejects a task when a referenced RFC is `Draft` / `Ready for Review` or its `## Open Questions` has an entry without a `**Resolution:**` / `RESOLVED:` / `✅ RESOLVED` marker. Override: `blocked.reason` in frontmatter.
- **DoR ingress gate:** `dor-ingress.yml` fails `Evaluate backlog tasks changed by PR` when a PR-staged task is `needs-clarification` with no `blocked.reason` override (use sparingly): [`dor-ingress-gate.md`](docs/operations/dor-ingress-gate.md).
- **Execution:** `/ai-sdlc execute <task-id | issue-number | gh:N>` is the default for internal work; autonomous drain is `/ai-sdlc orchestrator-tick` (+ `/ai-sdlc dispatch-worker`).
- **Done:** the task file moves to `backlog/completed/` in the originating PR's own diff.
- **Cross-repo writes:** declare `permittedExternalPaths: ['../repo/']` in task frontmatter; the PreToolUse hook resolves it from `<worktree>/.active-task` (fallback `AI_SDLC_ACTIVE_TASK_ID`), else cross-repo writes are denied.

### Lifecycle rules

- **Create-before-execution**: when a plan spans multiple tasks, create them ALL before dispatching. In Pattern C projects use `mcp__plugin_ai-sdlc_ai-sdlc__task_create` (routes writes to the active worktree); in plain projects `mcp__backlog__task_create` is fine.
- **Claim on start**: status → `In Progress`.
- **Complete = TWO steps**: `mcp__backlog__task_edit` (status, ACs, finalSummary) + `mcp__backlog__task_complete` (moves file). File location is source of truth. Run tests + lint before flipping.
- **Never leave `To Do` after implementation.** A task isn't closed until it's in `backlog/completed/`.
- `finalSummary` sections: Summary, Changes, Design decisions, Verification, Follow-up (each cites a task/issue id, "declined: <reason>", or "(none)"); template in the reference page.
- **No task for** inline review fixes (use the PR), trivial chores, or exploration/spikes.

## Releases

**CHANGELOG.md is managed exclusively by release-please. Contributors MUST NOT edit it manually.** Feature PRs MUST NOT touch it; if `scripts/check-changelog-edit.sh` WARNs, revert the CHANGELOG changes. Flow: [`release-flow.md`](docs/operations/release-flow.md).

**Landing the release PR.** The governance hook refuses raw `gh` merge commands (including `--auto` arming). Only when the operator explicitly instructs a release, run `node pipeline-cli/bin/cli-merge-if-eligible.mjs <pr> --source-kind release --arm` (drop `--arm` to merge now; `AI_SDLC_CALLER_ROLE=operator` from a plain shell). It verifies eligibility from GitHub; release merges also need `governance.allowMerge: onGreenClean` or `governance.allowReleaseMerge: true` on main. Never cut a release without an explicit operator instruction. Detail (also RFC dependency semantics and Pattern C routing): [reference](docs/operations/claude-md-reference-releases-rfcs-pattern-c.md).

**Package config.** Every non-`"private": true` workspace package MUST carry `"publishConfig": { "access": "public", "registry": "https://registry.npmjs.org/" }` (else npm rejects with E402 silently); `pnpm lint:publishable` catches regressions. A new publishable package also goes in `pnpm-workspace.yaml` and, if its version should be tracked, `release-please-config.json`.

## Plugin MCP server and Pattern C

The plugin MCP server resolves the project root from `AI_SDLC_PROJECT_ROOT`, `CLAUDE_PROJECT_DIR`, then a cwd walk-up for `backlog/`. In Pattern C (non-bare parent repo + `.worktrees/<task-id>/` isolates) the parent working tree is **read-only**; MCP writes route via `AI_SDLC_ACTIVE_TASK_ID`, else the newest `.worktrees/<id>/.active-task` sentinel, else refuse.

**Pattern C hard guards.** The parent working tree MUST be on `main` at all times, enforced by `scripts/check-orchestrator-state.sh` (Step 0 of every `/ai-sdlc execute` and `/ai-sdlc orchestrator-tick`) and `runParentBranchGuard()` in `pipeline-cli/src/orchestrator/loop.ts`. Parent on a non-main branch with a clean tree auto-recovers (`git checkout main && git reset --hard origin/main`); with a dirty tree it REFUSES and the tick aborts (operator: stash or commit in the parent, then reset).

**Sanctioned vs. ad-hoc reset:** `git reset --hard origin/main` is ONLY permitted when invoked by `scripts/check-orchestrator-state.sh` on a verifiably clean tree. Ad-hoc `git reset --hard` by the Conductor or a subagent is forbidden; if the script refuses, escalate to the Decision Catalog.
