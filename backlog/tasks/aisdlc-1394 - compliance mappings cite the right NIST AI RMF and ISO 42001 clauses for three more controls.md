## Description

**Gap.** Three control mappings cite clauses that do not say what the label claims, in all three implementations:

| Control | Current reference | Problem | Locations |
|---|---|---|---|
| provenance-tracking | `MAP 2.3 - AI System Provenance` | NIST AI 100-1 MAP 2.3 is scientific integrity and TEVV considerations, not provenance | `reference/src/compliance/mappings.ts:152`, `sdk-python/.../mappings.py:140`, `sdk-go/compliance/mappings.go:73` |
| complexity-routing | `MAP 1.5 - Risk Identification` | MAP 1.5 is organizational risk tolerances | `mappings.ts:176`, `mappings.py:160`, `mappings.go:77` |
| agent-memory | `Clause 7.1.6 - Organizational Knowledge` | ISO/IEC 42001 has no 7.1.6; the number is from ISO 9001 | `mappings.ts:228`, `mappings.py:203`, `mappings.go:88` |

**Source.** Found while reviewing fork PR #2683 (GitHub), which corrects four other rows (EU AI Act Art. 54 -> 57, Art. 61 -> 72; GOVERN 1.3 -> 2.1; MANAGE 2.2 -> GOVERN 3.2) in TypeScript and Python only. This task does not touch those four rows; they stay with #2683, and its Go change was added on the contributor branch by a maintainer on 2026-11-23 (commit 810197e, human-review now MAP 3.5).

## Fix

**Five-step review (requirements first).** 1. Requirement questioned: a mapping exists so an auditor can open the cited clause and find the control's subject; a wrong number is worse than none. 2. Deleted: the three wrong citations. 3. Simplified: one correction applied identically to the three files. 4. Accelerated: none. 5. Automated: a parity test so the three SDKs cannot drift.

- Pick the correct subcategory or clause for each control from the published texts (NIST AI 100-1 and its Playbook; ISO/IEC 42001:2023 clause and Annex A numbering) and cite the source in the PR body. If no clause fits a control, remove that row rather than keep a wrong one, and say so in the PR.
- Apply the same strings in TypeScript, Python and Go.
- Extend the existing parity manifest (`conformance/parity/manifest.json`, generated by `scripts/generate-parity-manifest.mjs`, checked by the Python and Go suites since AISDLC-1305) with the mapping rows (controlId, framework, frameworkReference), so the SDK suites fail when a reference string drifts. Today the manifest carries only `complianceControlIds`, which is why the Go mapping rows (landed with AISDLC-1306) kept the old references unnoticed.

## Acceptance Criteria

- [ ] #1 The three rows cite clauses whose published titles match the control, with sources in the PR body, identically in all three SDKs.
- [ ] #2 The parity manifest includes the mapping rows, and the Python and Go suites fail when any row differs from the reference.
- [ ] #3 The four rows #2683 corrects are unchanged by this task.
- [ ] #4 `pnpm build && pnpm test && pnpm lint && pnpm format:check` pass, and the Python and Go test suites pass.
