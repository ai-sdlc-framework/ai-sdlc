## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Context: on 2026-10-08, after the token audit (`docs/audits/2026-10-08-token-leak-loop-and-prose-automation-audit.md`, PR #1278), the operator instructed: "all agents save their handoff state continuously so we can clear at any moment without asking to build a handoff state, along with automatic clearing." Today the planner writes a dated memory file by hand, dispatch refreshes its handoff each tick (AISDLC-741), executors keep their state on the board, and clearing is either manual or bound to a tick. Nothing clears a session when its context crosses a threshold, so hierarchy sessions sat at 250k to 690k tokens of context for 20 hours, paying for that context on every turn.

Scope:

1. A deterministic `cli-hierarchy handoff write --role <r>` that each command body calls after every state change (a ruling recorded, a task claimed, a verdict written, a brief sent). It writes a role-specific file, `.ai-sdlc/dispatch/handoff/<session-name>.md` for dispatch and executors and the planner's dated memory file for the planner, generated from board and catalog state rather than from prose, so the file is never stale.
2. A `cli-hierarchy handoff read` that the loop bodies run first after any clear, so a fresh context resumes from the file and nothing else.
3. Automatic clearing. A hook (Stop or PostToolUse) or the AISDLC-743 context-meter mod reads the session's current context size from the usage fields in the transcript. Above a per-role threshold (planner 150k per AISDLC-741, dispatch and executors 120k, configurable in the `.ai-sdlc/dispatch` config) it runs `cli-hierarchy clear --self --resume-after <n>` with the role's resume command, for every role including the planner (the planner resumes with `/ai-sdlc:planner`). An executor is never cleared mid-task; the clear is deferred until its verdict is written.
4. The command bodies lose every "write a handoff before clearing" instruction and every "ask the operator before clearing" phrasing, because the handoff is always current and clearing is automatic.
5. `docs/operations/cli-hierarchy.md` documents the thresholds, the handoff files and the resume contract.
6. Hermetic tests cover handoff write and read and the threshold trigger.

Related: AISDLC-741, AISDLC-743, AISDLC-759, AISDLC-760 (idle paths).

Velocity impact (DEC-0048): removes a manual step and an operator wait; adds no gate.

Sequencing: none.

## Acceptance Criteria

- [ ] AC-1: Any hierarchy session can be cleared at any instant and resumes from its handoff file with no lost state (test: clear mid-tick, resume, same next action).
- [ ] AC-2: Handoff files are regenerated by the CLI from board and catalog state after each state change, with a test that a stale file is never read as current.
- [ ] AC-3: A session above its threshold clears itself within one turn without operator involvement; executors only between tasks.
- [ ] AC-4: No command body contains a manual handoff-writing instruction.
- [ ] AC-5: Thresholds are configurable and documented.
- [ ] AC-6: `pnpm test` passes.
