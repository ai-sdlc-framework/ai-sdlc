## Description

**Source.** DEC-0372, operator answer 2026-11-04 (`affected-packages`), tagged as a weakening of the verify-as-code control (AISDLC-1086). Lever 4 of the duplicate-test-run work.

**Today.** `runVerifyGate` runs the full chain (`pnpm build`, `pnpm test`, `pnpm lint`, `pnpm format:check`) after every developer return: the first, each verify fix round and each review iteration. A task can see about five full runs when a later round touched one test file.

## Fix

**Five-step review (requirements first).** 1. Requirement questioned: a later round must prove that what changed since the last clean pass still passes, plus everything that depends on it; CI's full suite still runs before merge. 2. Deleted: vitest runs of packages untouched since the last clean pass, in rounds after the first. 3. Simplified: package selection uses pnpm's own graph (`--filter "...[<treeSha or headSha>]"`, which includes dependents); no hand-written dependency walk. 4. Accelerated: later rounds run only the affected suites. 5. Automated: tests below.

**Rules (DEC-0372).**
- The first verify run of a task is always full.
- A later round is narrowed only when the previous verify record for this task has `ok: true` and `clean: true` and its `headSha` is an ancestor of the current HEAD. Otherwise the round is full.
- `pnpm build`, the root gate chain (`test:gates`, `rfc:check`, `dark-code:check`, `git-env-hygiene:check`, `lint:publishable`, `knowledge:check`), `pnpm lint` and `pnpm format:check` always run.
- Any changed path outside a workspace package (root files, `vitest.shared.mjs`, `tsconfig*`, `pnpm-lock.yaml`, `.github/`, `scripts/`, `.ai-sdlc/`) forces a full run.
- An unreadable record or a failed affected-set computation forces a full run. Narrowing fails closed.
- Touched packages keep running under `test:coverage` and the patch gate, as AISDLC-1185 set.

The record states `scope: full | affected` and the package list, so the reviewer prompt and the PR body can show what ran.

## Acceptance Criteria

- [ ] AC-1: The first run is full. A test asserts it even with a passing record from an earlier task attempt present.
- [ ] AC-2: A later round touching one package runs vitest for that package and its dependents only, plus the always-run commands. A test asserts the command list.
- [ ] AC-3: Each full-run trigger (non-package path, failed or dirty previous record, non-ancestor head, unreadable record, failed selection) yields a full run. One test per trigger.
- [ ] AC-4: The record carries `scope` and the package list; the PR body generated by step 11 shows the scope of the last verify run.
- [ ] AC-5: `docs/operations/quality-gate.md` describes the narrowing rules and cites DEC-0372.
