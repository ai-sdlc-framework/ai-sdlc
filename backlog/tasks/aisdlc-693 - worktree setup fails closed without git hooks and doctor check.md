## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
`core.hooksPath` is `.husky/_`, which is gitignored and generated by husky's `prepare`
script. A worktree installed with scripts disabled has no such directory, and git then
runs no pre-commit, commit-msg or pre-push hook, without any message. On 2026-10-03,
13 of 52 worktrees were in that state. Two pull requests (#1165, #1167) merged without
the local pre-push chain, a task file was left open on `main` because the task-move
hook never ran, and commit messages with scopes the lint rule rejects were never
checked.

A likely cause: `pnpm install` fails on the machine's default Node 22.19.0 with
`ERR_PNPM_UNSUPPORTED_ENGINE` because `lint-staged` requires Node 22.22.1 or newer,
while the root `package.json` declares `"node": ">=22"`. Sessions then installed with
scripts disabled.

Operator decision, 2026-10-03 (decision rubric): **worktree setup fails closed and a
doctor check reports the state**, chosen over committing the hooks directory (hooks
still need `node_modules`), repeating every local gate in CI (the task-move and signing
fixups need the local key) and a session-start warning (a warning is what was ignored).

## Conventions
- TypeScript strict, ESM, Vitest for packages, `node --test` for plugin scripts, 80%
  line coverage on new code. Tests use temporary git repositories and an injected
  command runner; they never run a real install.
- Adopter-facing: adopters may not use husky. The check asks git where hooks live
  (`git rev-parse --git-path hooks`) and whether a pre-push hook is expected, and it
  must not assume `.husky`.

## Scope
1. **Fail closed at setup.** After Step 3 creates a worktree and installs
   dependencies, verify that the directory git resolves for hooks exists and contains
   an executable `pre-push` whenever the repository's main checkout has one. When it is
   missing, run the repository's `prepare` script once; when it is still missing, the
   step fails with a message naming the directory and the command to generate it.
   The executor loop and the developer agent contract get the same check before the
   first commit.
2. **Never install with scripts disabled.** Remove or forbid `--ignore-scripts` in the
   pipeline's install commands and in the developer and executor instructions; a test
   asserts no command text in those files contains it.
3. **Node version.** Set the root `engines.node` to the lowest version that every
   dependency accepts, add a `.nvmrc` or equivalent pin that satisfies it, and make the
   setup step report the active Node version and the required range when install fails
   on an engine check, with the fix command.
4. **Doctor.** `/ai-sdlc doctor` gains a check that lists every worktree under
   `.worktrees/` whose hooks directory is missing, and reports the main checkout's
   state; `--fix` runs `prepare` in each affected worktree that has `node_modules`.
5. **Docs.** One paragraph in `CLAUDE.md` under Hooks stating that a worktree with no
   hooks directory runs no gate, and where the check lives.

## Acceptance Criteria
- [ ] In a fixture repository whose main checkout has a pre-push hook, worktree setup with a missing hooks directory runs `prepare` once and passes when the directory appears.
- [ ] When `prepare` does not produce the directory, setup fails with a message naming the directory and the command; no commit is attempted.
- [ ] A fixture repository with no hooks at all (adopter without husky) passes setup with no failure and no `prepare` run.
- [ ] No pipeline install command or agent instruction contains `--ignore-scripts` (asserted by a test over those files).
- [ ] An install that fails on an engine check produces a message with the active Node version, the required range and the fix command.
- [ ] `doctor` lists a worktree with a missing hooks directory, and `--fix` generates it when `node_modules` exists.
- [ ] Root `engines.node` matches what the lockfile's dependencies accept, and the version pin file satisfies it.
- [ ] `pnpm build && pnpm test && pnpm lint && pnpm format:check` pass.
