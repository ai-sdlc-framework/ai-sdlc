## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Context (bug report relayed from an adopter planner session, 2026-10-21 17:08Z; plugin 0.30.0, Claude Code 2.1.304).** A planner session ended a turn at 166,161 tokens of context, 16k past the 150,000 planner threshold, with 94 turns since its last clear. All four Stop hooks ran. `context-budget.sh` returned only its suggestion-level system message ("Context budget exceeded for planner ... Finish this unit and `/clear`"). `context-auto-clear.sh` produced no output at all: no block, no warning, and no scheduled `cli-hierarchy clear --self` followed by the role's resume command. The operator had to `/clear` by hand 21 s later, and the new session started with no resume command and no SessionStart prompt to run `handoff read --role planner`, so the operator also typed `/ai-sdlc:planner` by hand. The handoff file itself was intact.

Two defects, one gap:
- The over-budget planner Stop did not schedule the clear. Either the warn step never fired (the clear is documented as coming once the handoff is rewritten after the warning) or the clear waits for threshold plus 25 % (187,500 tokens), which is too late for a role whose whole purpose at that size is to stop and hand off.
- `context-auto-clear.sh` swallows every failure, so nothing says which branch it took (no CLI, CLI failed, warned, ran).
- After a manual `/clear` in a roster session, SessionStart does not point at `handoff read --role <role>` or the role's resume command.

**Five-step review (requirements first).**
1. Requirement questioned: "the auto-clear fires at threshold plus 25 %, with the threshold itself only a warning". For planner and dispatch, the handoff is regenerated by the CLI from board state on every state change, so there is nothing to wait for: the clear can fire at the threshold on the first turn boundary where the handoff file is current. The 25 % margin stays only as the hard ceiling for a session whose handoff is stale.
2. Delete: the silent failure path. Every exit of `context-auto-clear` writes one reason line (`no-cli`, `below-threshold`, `handoff-stale`, `warned`, `scheduled`, `failed:<msg>`) to the board log (`.ai-sdlc/dispatch/log/`, or the hook's stdout when the board is absent).
3. Simplify: the threshold logic lives in one place, `pipeline-cli/src/hierarchy/auto-clear.ts`; the shell hook only calls it and prints its reason. SessionStart in a roster session (hierarchy env present) always prints the two lines "run `handoff read --role <role>`" and the role's resume command, whether the clear was scheduled or manual.
4. Accelerate: an over-budget planner clears and resumes within one turn boundary instead of waiting for the operator to notice.
5. Automate: none beyond the above.

**Velocity impact.** Positive: removes the operator from the planner clear cycle and makes the next failure diagnosable from the log instead of from a pane.
