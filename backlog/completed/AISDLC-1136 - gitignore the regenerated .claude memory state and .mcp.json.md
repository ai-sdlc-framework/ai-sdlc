## Description

An audit of `.claude/` on 2026-10-31 (planner session, operator present) found the folder doing two jobs with no rule separating them. `.claude/memory/` held 50 untracked files: 41 durable agent memory notes written once, and 9 machine-regenerated files (`project_planner_handoff_YYYY_MM_DD.md`, `*_archive.md`, `handoff_ledger_planner.jsonl`) that `cli-hierarchy handoff write` rewrites on every state change. Nothing committed them and nothing ignored them. That is the gap that lost 61 of about 90 notes in the 2026-10-30 parent-checkout deletion (incident report line 77, "decide whether `.claude/memory` is tracked or backed up", still open). Three more local-only files have no repo rule: `.claude/settings.local.json` (ignored only by the operator's global git ignore), `.claude/transcripts/` (ignored only by `.git/info/exclude`) and the project `.mcp.json`, which the deletion also took and whose absence made every project MCP server fail to connect until it was regenerated by hand from the parent folder's copy.

PR #2212 (docs lane) commits the 41 durable notes and `MEMORY.md`. This task adds the rules and a template for the config file, which are outside the docs-only path list and so need a task and a reviewed PR. Operator ruling 2026-11-01: `.mcp.json` is ignored, not committed, because its `backlog-ent` and `backlog-io` entries point at sibling checkouts (`../ai-sdlc-enterprise`, `../ai-sdlc-io`) that differ per machine; a committed `.mcp.json.example` carries the shape instead.

## Implementation Notes

**Five-step review (requirements first).**
1. Requirement questioned: should `.claude/memory/` be ignored wholesale instead of split? No: the notes cannot be rebuilt (61 were lost once) and the docs-only path list already treats the folder as committable. Should the handoff files be committed too? No: they are rewritten every tick, the parent must stay clean for the orchestrator state check, and `handoff write` regenerates them from board and catalog state.
2. Delete: the local-only ignore entries for `.claude/transcripts/` in `.git/info/exclude` and `**/.claude/settings.local.json` in the operator's global ignore become redundant once the repo rules land (the operator removes them; the task does not touch files outside the repo).
3. Simplify: six patterns, one comment block, one test file.
4. Accelerate: a fresh clone connects its MCP servers after one copy of the template, with no hand-written config.
5. Automate: the `check-ignore` test keeps the split from drifting when a new machine-written file appears in the folder.

Velocity impact: none on pushes; removes one recurring manual repair after disk loss.

Out of scope: moving memory to a different folder; changing what `handoff write` produces; the Claude Code runtime files already covered by `.git/info/exclude` (scheduled_tasks, worktrees, mailbox), whose names change between harness versions.
