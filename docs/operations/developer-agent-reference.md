# Developer agent reference

Worked examples, incident history and long-form procedures moved out of `ai-sdlc-plugin/agents/developer.md` by AISDLC-651.2. The agent definition keeps the full return contract, the Definition of Done and the hard rules (rendered from `ai-sdlc-plugin/hooks/lib/prompt-rules.js`); this page is the "why" behind them. See also [prompt-rules.md](./prompt-rules.md).

## Why rebase-before-push is mandatory

In an autonomous-loop / parallel-execution environment `main` moves while a task runs. A branch that was current at start-of-task but stale at end-of-task opens BEHIND `main`, GitHub auto-merge cannot proceed without a rebase, and the operator has to rebase manually or wait for a follow-up commit to retrigger CI on the rebased SHA. Cost per occurrence: 2x CI cycles plus manual operator action plus delay before merge. The fix is unconditional: fetch and rebase before every push, even if the task just started. `git fetch origin main && git rebase origin/main` is a proactive precondition of every push, not a reactive cleanup after a conflict surfaces.

Returning without rebasing, pushing or opening the PR is incorrect: "my role ends at commit, the orchestrator handles push + PR" is the failure mode the developer prompt was rewritten to eliminate (observed in AISDLC-160, 161, 162).

## Mechanical vs semantic rebase conflicts

Mechanical (resolve in place):

- `pnpm-lock.yaml` regenerated by a sibling `pnpm install`: accept incoming, run `pnpm install` to regenerate against the new tree, `git add pnpm-lock.yaml`.
- `CHANGELOG.md` conflicts on a feature branch mean the branch wrongly contains CHANGELOG edits: remove the CHANGELOG diff rather than merging both sides (AISDLC-401, release-please owns it).
- `package.json` `bin:` list additions from several branches: concatenate both sides, preserve alphabetical order if the list is sorted.
- Prettier reformat drift: accept the side matching the latest formatter, `pnpm format`, re-stage.
- `.active-task`: per-worktree sentinel, gitignored since AISDLC-155; a conflict means a stale tracked instance, so `git rm` it and continue.
- New file additions in non-overlapping paths: take both sides.

Semantic (stop, leave the rebase `git rebase --abort`-recoverable, report in `notes`):

- Code conflicts where both sides modified the same function body.
- Structurally conflicting schema changes (different field names, incompatible types).
- Test changes where both sides modified the same assertions or cases.
- Anything where resolution requires understanding intent.

A reported semantic conflict is recoverable; a wrong auto-resolve is a silent regression that may not surface until someone else hits a runtime bug.

## Worked examples

### CORRECT

```
[ai-sdlc-progress] commit: a1b2c3d feat(spec): add docs sync (AISDLC-68)
[ai-sdlc-progress] rebase: fetched origin/main; rebased clean (0 conflicts)
[ai-sdlc-progress] push: pushed ai-sdlc/aisdlc-68-docs-sync to origin (--force-with-lease)
[ai-sdlc-progress] pr: opened https://github.com/org/repo/pull/4321
... return JSON with prUrl: "https://github.com/org/repo/pull/4321"
```

The PR opens at-or-ahead of `main`, `auto-enable-auto-merge.yml` arms auto-merge, CI runs once on the rebased SHA, and the PR merges as soon as required checks pass.

### CORRECT with a mechanical conflict

```
[ai-sdlc-progress] commit: a1b2c3d feat(spec): add docs sync (AISDLC-68)
[ai-sdlc-progress] rebase: fetched origin/main; pnpm-lock.yaml conflict — accepted incoming, ran pnpm install, re-staged
[ai-sdlc-progress] rebase: rebase complete (1 mechanical conflict resolved)
[ai-sdlc-progress] push: pushed ai-sdlc/aisdlc-68-docs-sync to origin (--force-with-lease)
[ai-sdlc-progress] pr: opened https://github.com/org/repo/pull/4321
```

### WRONG: skip rebase, push behind

```
[ai-sdlc-progress] commit: a1b2c3d feat(spec): add docs sync (AISDLC-68)
[ai-sdlc-progress] push: pushed ai-sdlc/aisdlc-68-docs-sync to origin
[ai-sdlc-progress] pr: opened https://github.com/org/repo/pull/4321
```

This looks correct because `prUrl` is populated, but the PR is BEHIND `main` from the moment it opens, so auto-merge cannot proceed (2x CI cycles, manual action, merge delay).

### WRONG: commit landed but no push

```
[ai-sdlc-progress] commit: a1b2c3d feat(spec): add docs sync (AISDLC-68)
... return JSON with commitSha set, prUrl: null
... notes: "commit landed on the feature branch; orchestrator handles push + PR"
```

A failed run: the orchestrator treats `prUrl: null` as a hard failure. Even when rebase, push or `gh pr create` fail for an environmental reason, attempt them and report the failure in `notes`.

### WRONG: auto-resolved a semantic conflict

```
[ai-sdlc-progress] rebase: source-file conflict in pipeline-cli/src/steps/step-7-attest.ts — picked HEAD side
```

Picking a side in a function body or test assertion is guessing. A correct escalation:

```
[ai-sdlc-progress] rebase: SEMANTIC conflict in pipeline-cli/src/steps/step-7-attest.ts — escalating
... return JSON with commitSha set, prUrl: null
... notes: "rebase aborted: semantic conflict in pipeline-cli/src/steps/step-7-attest.ts at signAttestation() — both branches modified the envelope assembly. Operator must resolve."
```

## Rename / move / delete: update inbound references (AISDLC-486)

"Backlog Drift" is a REQUIRED CI gate. Renaming, moving or deleting a file referenced by a backlog task fails it (`✗ Referenced file no longer exists`) and stalls the PR.

1. Before renaming or deleting: `grep -rl "old/path/to/file.md" backlog/`; update every referencing task in the same commit (`npx backlog-drift fix --task <TASK-ID>` auto-fixes one task).
2. Before pushing: `npx backlog-drift check` and fix every `error`-severity issue. There is no local pre-push or pre-commit drift gate (AISDLC-712, DEC-0056); the CI check is the gate.

Motivating incident: PR #789 renamed `ai-sdlc-plugin/commands/review.md` to `review-pr.md`; backlog task AISDLC-71 referenced the old path, so `backlog-drift check` failed until corrected by hand.

## Decision Catalog escalation for blocking Open Questions (AISDLC-298, AISDLC-480)

When an RFC `## Open Questions` entry without a `**Resolution:**` marker blocks or constrains the work, do BOTH:

Step A, before returning your JSON:

```bash
node pipeline-cli/bin/cli-decisions.mjs escalate \
  --task-id "AISDLC-NNN" \
  --source-worktree "$(pwd)" \
  --summary "<one-line: what decision is blocking>" \
  --scope "rfc:RFC-XXXX" \
  --option "opt-a:<first option description>" \
  --option "opt-b:<second option description>" \
  --body "OQ reference: RFC-XXXX §OQ-N. <context>" \
  --format json
```

Step B: return `prUrl: null` with `notes` naming the RFC, the OQ number, the decision id just created and the options.

Never write `**Resolution:**`, `RESOLVED:` or a check-mark RESOLVED marker yourself; that is exclusively the operator's role after a walkthrough (AISDLC-271 / RFC-0031: an agent decided an entire RFC's OQs inline). A genuinely non-blocking OQ gets a documented assumption in the PR body and no `cli-decisions escalate` (the catalog is for blockers only). `cli-decisions show <id>` gives the operator full context and `cli-decisions answer <id> <optionId>` resolves it; see [RFC-0035](../../spec/rfcs/RFC-0035-decision-catalog-operator-routing.md) and [dispatched-session-decisions.md](./dispatched-session-decisions.md).

## Pre-work flags (AISDLC-308)

If the task body says "Pre-work required", "Pre-conditions:", "operator walkthrough needed" or references an RFC with unresolved OQs: STOP, return `prUrl: null` with `notes` naming the unmet precondition and what the operator must do. Do not implement, decide OQs inline, file follow-up tasks or dispatch subagents on the assumption the precondition holds. The PR #481 audit (2026-05-16) found an agent ignoring its own "operator walkthrough required" note 1.5 hours later.

## Stash safety (AISDLC-611)

The git stash stack is ONE resource shared across the main checkout, every `.worktrees/<id>/` and any concurrent session. A bare `git stash` then `git stash pop` can apply and drop a PRE-EXISTING stash that belongs to the operator or a sibling session (real incident: local-trades LT-595, HIGH-3, recovered only via `git stash store` from a dangling commit).

Safe pattern: prefer a temporary WIP commit (`git add -A && git commit -m "wip: aisdlc-nnn checkpoint"`, then `git reset --soft HEAD~1` to unwind). If you must stash: `git stash push -u -m "<unique-tag>"`, restore by exact ref with `git stash apply <ref>` (never `pop`), then `git stash drop <ref>`. `ai-sdlc-plugin/hooks/enforce-blocked-actions.js` blocks `git stash pop`, `git stash clear` and bare `git stash drop` regardless of the prompt; bare `git stash`, `push`/`save`, `apply`, `list`, `show` and `drop <ref>` are allowed.

## CI-skip markers (AISDLC-88)

GitHub Actions parses five literal substrings case-insensitively and suppresses every workflow on a commit carrying one, which silently disables verify-attestation and ai-sdlc-review. Backtick-wrapping does not defeat the parser; use the paren form `(skip ci marker)`. `scripts/check-skip-ci-marker.sh` blocks the push. The legacy `chore(ci): sign review attestation` commits by `ai-sdlc-ci-attestor[bot]` remain exempt so replayed history does not strand pushes; the attestor itself was removed (AISDLC-140 sub-4, AISDLC-152).

## Governance config paths

The PreToolUse hook blocks `.ai-sdlc/**` and `.github/workflows/**` for runs marked untrusted (`AI_SDLC_UNTRUSTED_RUN`; internal sessions may edit governance config when the task names it). `.github/workflows/**` is otherwise refused only when the project's `.ai-sdlc/agent-role.yaml` lists it under `blockedPaths`; it is not blocked by default, so edit workflows when the task needs it and the project permits. Runtime artifacts (attestations, reviews, transcript leaves, the decision log, the dispatch board) are written through their CLIs.

## Force-push and merge policy

Force-push is `--force-with-lease` only (allowed by default via `allowForcePush: leaseOnOwnBranch`, no operator prompt) and is REQUIRED after the mandatory rebase, because the rebase changes the SHA; plain `--force` stays forbidden. Merging follows `governance.allowMerge` in `.ai-sdlc/agent-role.yaml`, rendered into the session hard rules; when it permits merging the only path is `cli-merge-if-eligible`.
