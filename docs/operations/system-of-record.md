# System of record per artifact

Project state lives in several stores. This page says which one wins when they disagree, and where this project diverges from the human-approval stages of the AI-native SDLC playbook. It adds no new rule; every row links to the doc that states the rule today.

## Which store wins

| Artifact                                              | System of record                                                                                                  | Writer                                                                  | What overrides it                                                                                                  | Rule stated today                                                                                                                                  |
| ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| Backlog task                                          | The file in `backlog/tasks/` (open) or `backlog/completed/` (closed); file location is the source of truth        | Planner and executors through the `mcp__backlog__*` tools               | Nothing for completion state; a task with `blocked.reason` skips the DoR gates                                     | [`backlog-and-execution-reference.md`](backlog-and-execution-reference.md)                                                                         |
| GitHub issue                                          | The issue itself on the `gh:<n>` execution path (no task file is created); otherwise a mirror for external input  | External contributors; internal work is filed as backlog tasks          | A backlog task for the same work                                                                                   | [`backlog-and-execution-reference.md`](backlog-and-execution-reference.md)                                                                         |
| Pull request                                          | GitHub: the PR, its checks and the `ai-sdlc/pr-ready` rollup decide mergeability; `landed` (merged) is the only trigger for `done/` | The developer agent opens it as a draft; the orchestrating command marks it ready | Branch protection and the `ai-sdlc/pr-ready` rollup                                                                 | [`quality-gate.md`](quality-gate.md), [`merge-without-queue.md`](merge-without-queue.md)                                                           |
| Decision record                                       | The decision catalog under `.ai-sdlc/_decisions/` on `main`; a record not yet on `main` is not authority         | `cli-decisions add`, `answer`, `escalate`                               | A later record that supersedes it, or an operator override inside the override window                              | [`decision-authority.md`](decision-authority.md)                                                                                                   |
| RFC                                                   | `spec/rfcs/RFC-NNNN-*.md` on `main`, by lifecycle status (Signed Off, Implemented)                                | RFC authors; Open Question resolution is the operator only              | Sign-off by the operator; a developer agent never resolves an Open Question                                        | [`spec/rfcs/README.md`](../../spec/rfcs/README.md)                                                                                                 |
| Dispatch board (`.ai-sdlc/dispatch/`)                 | The files under `.ai-sdlc/dispatch/`, as written by the hierarchy tooling                                          | `cli-hierarchy` and the dispatch session                                | The backlog task file and the PR state; the board is a work queue, not a record of completion                      | [`session-hierarchy.md`](session-hierarchy.md), [`cli-hierarchy.md`](cli-hierarchy.md)                                                             |
| Attestation envelope                                  | The signed envelope committed under `.ai-sdlc/attestations/` and verified by CI                                   | The signing CLI at the end of review; agents never hand-write one       | Nothing; a missing or invalid signature fails the gate                                                             | [`attestation-reference.md`](attestation-reference.md)                                                                                             |
| Handoff memory                                        | The planner's memory notes (`.claude/memory/`, newest `RESUME HERE` block)                                         | The planner session                                                     | Any of the artifacts above: memory is a hint for resuming and never beats the repository                           | [`session-hierarchy.md`](session-hierarchy.md)                                                                                                     |

Rule of thumb: the repository on `main` beats chat, memory and the dispatch board. When two repository artifacts disagree, the row above names the winner.

## Human approval: where this project diverges from the playbook

The playbook puts a human approval at each stage below. This project replaces most of them with the decision rubric and a gate, and keeps a person only for class (c) steps.

| Playbook approval point | This project's replacement                                                                                                                   | Governing doc                                                                                                                                                  |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Plan                    | The planner files tasks; the Definition of Readiness gates and the decision rubric (classes a and b) stand in for a plan sign-off. RFC sign-off and Open Question resolution stay with the operator. | [`decision-authority.md`](decision-authority.md), [`dor-ingress-gate.md`](dor-ingress-gate.md), [`spec/rfcs/README.md`](../../spec/rfcs/README.md) |
| Merge                   | No human click: `cli-merge-if-eligible` merges once `ai-sdlc/pr-ready` is green and reviewers and attestation have signed (`governance.allowMerge`). | [`quality-gate.md`](quality-gate.md), [`merge-without-queue.md`](merge-without-queue.md)                                                                       |
| Release                 | Operator-only (class c): the release-please PR lands only on the operator's explicit instruction.                                            | [`release-flow.md`](release-flow.md), [`decision-authority.md`](decision-authority.md)                                                                         |
| Policy change           | Tightening a control is class (a); loosening one is a class (b) weakening that never self-applies on a lapse; legal, money and credentials are class (c). | [`decision-authority.md`](decision-authority.md)                                                                                                               |
