# Tooling limitations register

Every external ceiling (GitHub API, `gh`, git, Actions) the framework works around, with the symptom when it is hit, where its headroom is read, the workaround that holds it off, and how it scales. Neither limit is ours: the workarounds hold the ceiling off, they do not remove it. Adopters running many concurrent agents on one codebase, in particular enterprise organisations, meet these ceilings earlier than we do.

The `Headroom read at` column is either a backticked repository path of the surface that reports the metric, or the word `unmeasured` (no instrumentation yet; the cell then gives the manual command). `scripts/check-tooling-limitations.test.mjs` enforces this and that every required ceiling has a row. Add a row whenever a new ceiling is worked around.

| Ceiling | Symptom when hit | Headroom read at | Workaround | Scaling note |
|---|---|---|---|---|
| GitHub user token, core REST budget (5,000 per hour) | `API rate limit exceeded` for the user; `gh` calls fail until the hourly reset | unmeasured (`gh api rate_limit --jq .resources.core`) | Fewer `gh` calls per tick, cached probes, `rate-limited` rerun class in `docs/operations/cli-hierarchy.md` | Per user token; enterprise cloud raises it (15,000 per hour for GitHub Enterprise Cloud apps) |
| GitHub user token, GraphQL points budget (5,000 points per hour) | `gh pr list` and `gh pr view` fail on GraphQL cost | unmeasured (`gh api rate_limit --jq .resources.graphql`) | Prefer REST endpoints for polling; batch fields into one query | Per user token; points scale with query size, not call count |
| Secondary rate limits (concurrency and burst) | A call is refused while `rate_limit` still shows thousands remaining; `Retry-After` header | unmeasured (no counter; read the refusal text) | Pace calls (about 20 s between pushes), serialise writes, back off on `Retry-After` | Per user and per installation; not visible in `rate_limit` |
| Actions `GITHUB_TOKEN` per repository (1,000 requests per hour) | Gate jobs fail in under 30 s with `API rate limit exceeded for installation`; `ai-sdlc/pr-ready` goes red | `pipeline-cli/src/hierarchy/pr-state.ts` (the rate-limited PR state, listed in `docs/operations/cli-hierarchy.md`) | One CI run per PR, rerun failed jobs once per head SHA at or after the next full hour | Per repository; GitHub Enterprise Cloud raises it to 15,000 per hour |
| GitHub installation `GITHUB_TOKEN`, REST bucket (5,000 calls per hour, shared by every CI job) | Every gate job fails with `API rate limit exceeded for installation` (`ai-sdlc/issue-link`, the Governance gate OQ scan, Dependency review "not supported"); each rerun spends more of the bucket | `pipeline-cli/src/cli/file-pacing.ts` (`cli-file --pr` prints the remaining calls and reset time at the start of each filing) | `cli-file --pr` spaces filings (default 15 minutes, `--spacing-minutes` or `AI_SDLC_FILE_SPACING_MINUTES`) and waits or, with `--queue`, queues a brief for the next window (AISDLC-986); per-job call reduction tracked here | Per installation; shared across all repositories and jobs of the app |
| Search API (30 requests per minute) | Search-backed lookups return 403 or 422 under burst | unmeasured (`gh api rate_limit --jq .resources.search`) | Use list endpoints or local state instead of search | Per user token; same on every tier |
| `gh run rerun` argument shape | Accepts only a run id, not a PR, SHA or workflow name | `docs/operations/cli-hierarchy.md` (the rate-limited recovery row names the run id lookup) | Resolve the id with `gh run list --commit <sha> --workflow ai-sdlc-gate.yml` first | Tool shape, not a quota; unchanged across tiers |
| Git loose-object growth stops automatic gc in the parent checkout | `git gc --auto` declines to run, repository grows, status and fetch slow down | unmeasured (`git count-objects -vH` in the parent checkout) | Run `git gc` from a quiet parent checkout; keep the parent on `main` and idle | Per clone; grows with concurrent worktrees and agent churn |
| Worktree count per repository (about 80 observed) | Slower `git worktree list`, fetch and status; disk pressure | unmeasured (`git worktree list \| wc -l`) | `/ai-sdlc cleanup` removes merged worktrees; cap concurrent executors | Per clone; every worktree shares one object store |
| GitHub Free private repository: no auto-merge (`allow_auto_merge` false, no branch protection or rulesets) | Arming a clean PR lands it at once under the caller's token; a naive "armed" report is wrong | unmeasured (`gh api repos/<owner>/<repo> --jq .allow_auto_merge`) | `cli-merge-if-eligible --arm` reads `allow_auto_merge`: false lands an eligible PR directly (`landed`) or reports `not-armable`; true reports `armed` only after the PR read-back shows an `autoMergeRequest` (AISDLC-1009) | Plan-level; GitHub Pro or Team enables auto-merge and branch protection on private repositories |
